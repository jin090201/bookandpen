# 아키텍처 (architecture.md)

> 작성: AI 초안 / 확인: 개발자(아키텍처 타당성, 기술 선택)

## 1. 한눈에 보기
```
브라우저 (모바일)
 ├─ React 앱 (Vite 번들)
 │   ├─ App.jsx ........ 상태(data)·화면 전환·데이터 변경 함수
 │   ├─ components/ .... BookList(책장·즐겨찾기·설정), BookDetail, ScanEditor, CropView(인식할 부분 자르기), CalendarView(독서 달력), StatsView(통계), SearchView(책장 검색의 필사 결과),
 │   │                    공통: Pager(목록 나누기, 한 화면 5개는 LIST_PAGE_SIZE 한 곳), Chip(선택 칩), Note(굵은 글씨·팁·주의 상자), EmptyState(빈 화면 안내 카드), ProgressBar(책별 진행률 막대)
 │   └─ lib/ ........... storage(저장·백업·설정·내보내기·종류 거르기·페이지 표기), date(날짜 표기), calendarExport(읽기용 문서 만들기), ocr, postprocess
 ├─ LocalStorage ....... 기록(reading-notes:v1), 설정(reading-notes:settings:v1), 달력 설정(reading-notes:calendar:v1), 마지막 백업 시각(reading-notes:backup:v1), 알림 띠를 닫은 시각(reading-notes:remind:v1), 최근 검색어(reading-notes:search:v1), 올해 완독 목표(reading-notes:goal:v1), 깨진 기록 원본 보관(reading-notes:v1:corrupt)
 ├─ Tesseract.js ....... 브라우저 안 OCR (kor+eng)
 └─ (외부) 언어 데이터·구글 폰트 내려받기 (인터넷)
서버 없음 → GitHub Pages가 정적 파일만 제공
```

## 2. 기술 선택과 이유
| 영역 | 선택 | 이유 | 대안·주의 |
|---|---|---|---|
| UI | React 18 | 상태 기반 화면, 익숙한 도구 | 앱이 커지면 라우터 도입 검토 |
| 빌드 | Vite 5 (`base: './'`) | 빠른 개발 서버, 하위 경로 배포 가능 | 일반 Live Server로는 JSX 실행 불가 → `npm run dev` |
| 스타일 | Tailwind 3.4 + CSS 변수 | 색·글꼴을 변수로 연결해 테마·설정 즉시 반영 | 기본 `stone`·`white` 색을 변수로 덮어씀 |
| OCR | Tesseract.js v5 (kor+eng) | 서버 없이 사진이 기기 밖으로 안 나감 | 인식 정확도·속도 한계(아래 4절) |
| 저장 | LocalStorage | 서버·로그인 불필요 | 용량 약 5MB, 브라우저 데이터 삭제 시 소실 → 백업 기능으로 보완 |
| 배포 | GitHub Pages + Actions | 무료 정적 호스팅 | 서버 기능이 필요해지면 재검토 |

## 3. 화면 전환·상태
- 라우터 없이 `view`(books / detail / scan)와 `tab`(shelf / favorites / record / settings) 상태로 전환.
- 모든 기록은 `App`의 `data` 하나에 두고, 바뀔 때마다 `saveData`로 저장. 저장 실패 시 상단에 경고 표시. 같은 브라우저의 다른 탭에서 기록(`reading-notes:v1`)이 바뀌면 `storage` 이벤트로 알아차리고 최신 기록을 다시 읽어 와, 나중에 저장한 탭이 앞의 변경을 덮어쓰지 않게 함.
- 설정은 `useSettings` 훅과 `updateSettings`(저장 + 즉시 적용 + 이벤트 알림)로 화면 간 공유.
- 삭제 직전의 책·필사를 `undoList`에 쌓아 두고(최대 5개, 항목마다 삭제한 때부터 10초 뒤에 사라짐), "되돌리기"를 누르면 가장 최근 것부터 id 기준으로 합칩니다(그 사이 바뀐 다른 기록은 건드리지 않습니다). 모든 기록 삭제 때는 목록을 비웁니다.
- 백업 알림은 `backupReminders`가 마지막 백업 후 30일 경과 또는 저장 공간 80% 이상일 때 안내 문구를 만들고, 설정에서 백업하면 이벤트로 알림 띠를 갱신합니다. 백업 시각(`markBackup`)은 파일 만들기·내려받기 시작(`downloadTextFile`이 true)에 오류가 없었을 때만 기록하며, 시각 저장에 실패하면 이벤트를 보내지 않고 화면에 알립니다(브라우저의 실제 저장 여부는 웹에서 알 수 없음). 띠의 ✕를 누르면 닫은 시각을 저장해(`reading-notes:remind:v1`) 7일 동안 백업 문구를 숨기고, 저장 공간 경고는 닫을 수 없어 계속 표시합니다.

## 4. 주요 흐름
**필사 추가**: 사진 선택 → `CropView`에서 인식할 부분을 고름(또는 "자르지 않고 인식") → `prepareImage`(고른 영역만 잘라 쓰고, 긴 변 2800px까지 축소하는 비율은 자르기 전 사진 전체 기준, 작은 사진은 키우지 않음 → 흑백 변환·대비 늘리기) (필사 화면의 미리보기는 `makePreview`로 인식에 쓴 부분만 잘라 보여 주며, 만들지 못하면 사진 전체를 보여 줌) → Tesseract 워커(싱글톤, 최초 1회 언어 데이터 로드) → 원문과 "신뢰도 70 미만 단어 목록"(`recognizeImage`가 함께 돌려주며 기호·한 글자 한글은 제외, 화면에서는 사진 한 장당 10개 초과 시 그 사진의 목록을 만들지 않고 안내로 대체, 칩을 누르면 입력칸에서 그 단어를 선택하고 위치로 스크롤, 다른 단어의 일부가 아닌 따로 쓰인 위치를 먼저 찾음) → `postprocess`(하이픈·강제 줄바꿈·공백 정리) → 사용자가 수정(확인 목록의 단어를 누르면 본문에서 선택) → 저장.
**백업 가져오기**: 파일 선택 → `parseBackup`(검증·값 고치기) → `planImport`(새로 들어오는 수·건너뛰는 수 계산) → 설정의 요약 카드에서 사용자가 확인 → `App.importBackup`이 같은 `planImport`로 합침(취소하면 아무것도 바뀌지 않음).
**설정 적용**: 선택 → `saveSettings` → `applySettings`가 `<html>`에 글자 크기, 글꼴, 색 변수(`--c-*`, `--accent`, `--dot`)를 설정 → Tailwind 색이 즉시 바뀜. '기기 설정'은 `prefers-color-scheme` 변경도 감지.

## 5. 위험·한계
| 항목 | 내용 | 완화 |
|---|---|---|
| 데이터 소실 | 브라우저 데이터 삭제 시 기록 사라짐 | 백업 내보내기·가져오기, 안내 문구 |
| 시간대 | 기록 시각은 UTC로 저장하고 달력·통계는 기기의 현재 시간대 날짜로 묶음 | 한국에서만 쓰면 문제없음. 다른 시간대의 기기에서 열면 같은 기록이 하루 다르게 묶일 수 있음(알려진 한계, 기록 날짜를 따로 저장하는 방식은 해외 사용이 생기면 검토). 책장의 "오늘 / N일 전"은 달력과 같은 날짜 기준 |
| 용량 | LocalStorage 약 5MB | 텍스트만 저장, 저장 실패 경고, 입력 한도(본문 5,000자·메모 500자·책 제목 100자·저자 50자·출판사 50자·사진 10MB), 80% 이상 사용 시 백업 알림 |
| 실수로 삭제 | 확인 창 후에도 되돌리고 싶을 수 있음 | 삭제 직후 10초간 되돌리기, 연속 삭제는 최대 5개까지 쌓아 최근 것부터 한 개씩 되돌림 (모든 기록 삭제는 제외) |
| OCR 품질 | 곡면 페이지·흐린 사진, 뒷면 글자 비침·그림자, 영문 뒤에 붙은 한글 조사에서 오인식 | 해상도 2800px, 흑백·대비 보정, 인식할 부분 자르기, 폰 글자 복사 안내, 직접 수정 UI, 신뢰도가 낮은 단어 확인 목록(글자 하나가 비슷한 글자로 바뀐 오류는 엔진이 높은 신뢰도로 내놓아 잡지 못함) |
| 외부 의존 | 첫 인식 때 언어 데이터 다운로드, 구글 폰트 | 이후 캐시, 폰트는 시스템 글꼴로 대체 |
| CSS `zoom` | 손글씨 크기 보정에 사용. 필사 본문 글꼴이 나눔손글씨 펜일 때 제목·필사 본문에 1.25배가 적용되고(다른 글꼴은 1.0), 글자 크기 단계와 곱해집니다(보통 18px 기준 본문 22.5px, 제목 약 33.8px). 값은 `FONT_OPTIONS.pen.scale`에서 정하며 설정에 저장되지 않습니다 | 지원 안 하는 브라우저에서는 보정만 빠짐 |

## 6. 보안·공개 범위
- 저장소(공개): https://github.com/jin090201/bookandpen · 배포: https://jin090201.github.io/bookandpen/
- 서버·인증 정보 없음. `.gitignore`가 키·인증서·환경 변수·`.npmrc`·테스트 파일·백업 JSON·사진을 제외합니다.
- `public/` 폴더 안의 이미지(아이콘·로고)는 예외로 올라갑니다. 다른 폴더의 이미지는 `.gitignore`에 예외 한 줄을 추가해야 합니다.
- 시작할 때 `navigator.storage.persist()`로 브라우저가 기록을 임의로 지우지 않도록 요청합니다(허용 여부는 브라우저가 결정).
- CSP(콘텐츠 보안 정책)를 배포 빌드에만 `<meta>`로 넣습니다(`vite.config.js`의 `cspPlugin`). 개발 서버(`npm run dev`)에는 적용하지 않습니다. GitHub Pages는 HTTP 헤더를 바꿀 수 없어 meta 방식이며, `frame-ancestors` 등 일부 지시어는 meta에서 동작하지 않습니다.
- 허용 대상: 자기 자신(`'self'`), OCR 엔진·언어 데이터용 `cdn.jsdelivr.net`, 글꼴용 `fonts.googleapis.com`·`fonts.gstatic.com`, 워커용 `blob:`, 사진 미리보기용 `data:`·`blob:`, wasm 실행용 `'wasm-unsafe-eval'`. OCR이나 글꼴이 막히면 콘솔의 `Refused to ...` 오류를 보고 해당 주소만 추가합니다.
- 검색 엔진 차단(robots.txt, noindex)은 적용하지 않기로 했습니다(현 상태 유지).
